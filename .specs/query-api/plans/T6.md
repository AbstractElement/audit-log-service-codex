# T6 — API layer: switch `GET /audit-events` to keyset, add `@RestControllerAdvice`

*Refactor `AuditEventController` to consume the new service method, accept
the new query parameters, and return the new envelope. User-visible
breaking change.*

## Why this task exists

T1–T5 are all additive — they ship new types, ports, adapters, and a new
service method, but the controller still serves the legacy offset
endpoint. T6 is the **breaking change**: it flips `GET /audit-events`
from `(actor, resource, from, to, limit, offset) → List<…>` to the new
cursor-based contract.

This task also introduces the project's first `@RestControllerAdvice`.
Until now no global error handler existed; Spring's default
`{ timestamp, status, error, message, path }` shape would surface for
validation failures, which doesn't match the design's structured
`{ error, message, field? }` shape. The advice lives in the API layer
because translating Application-layer `ValidationException` into HTTP is
explicitly an API concern (AC-5.1).

T7 cleans up the legacy code paths after this PR has soaked.

## Requirements covered

- **AC-1.1** (Event-driven) WHEN the client sends `GET /audit-events` with
  ISO-8601 UTC `from`, `to`, and at least one of `actor` or `resource`,
  THE SYSTEM SHALL return HTTP 200 with the matching events ordered by
  `event_timestamp` DESC, then `id` DESC.
- **AC-1.3** (Unwanted) IF `from` is missing OR `to` is missing, THE SYSTEM
  SHALL return HTTP 400.
- **AC-1.4** (Unwanted) IF neither `actor` nor `resource` is supplied, THE
  SYSTEM SHALL return HTTP 400.
- **AC-1.5** (Unwanted) IF `from` is after `to`, THE SYSTEM SHALL return
  HTTP 400.
- **AC-1.6** (Unwanted) IF `to − from` exceeds 7 days, THE SYSTEM SHALL
  return HTTP 400.
- **AC-1.7** (Unwanted) IF `from` or `to` is not a valid ISO-8601 UTC
  instant, THE SYSTEM SHALL return HTTP 400.
- **AC-2.4** (Unwanted) IF a `cursor` is supplied together with any of
  `actor`, `resource`, `from`, or `to`, THE SYSTEM SHALL return HTTP 400.
- **AC-2.5** (Unwanted) IF the supplied `cursor` is malformed, THE SYSTEM
  SHALL return HTTP 400.
- **AC-2.6** (Ubiquitous) THE SYSTEM SHALL default `limit` to 100 and cap it
  at 500.
- **AC-2.7** (Unwanted) IF `limit` exceeds 500 OR is less than 1, THE SYSTEM
  SHALL return HTTP 400.
- **AC-4.1** (Ubiquitous) THE SYSTEM SHALL include `id`, `timestamp`,
  `actor`, `action`, `resource`, `outcome`, and `context` on every item.
- **AC-4.2** (Ubiquitous) THE SYSTEM SHALL serialize `timestamp` as the same
  instant the event was recorded with, in UTC.
- **AC-5.1** (Ubiquitous) THE SYSTEM SHALL define cursor and request types in
  the Application layer; the API layer SHALL only translate HTTP ↔
  Application DTOs.
- *Out of scope* (requirements.md): "Backwards-compatibility shim for the
  current offset/limit pagination — callers will migrate to cursor
  pagination as part of this change."

## Design references — extracts inlined

### API contract — first-page request

| Param      | In    | Type            | Required             | Notes                                       |
|------------|-------|-----------------|----------------------|---------------------------------------------|
| `actor`    | query | string          | One of actor/resource required | Exact match; case-sensitive.       |
| `resource` | query | string          | One of actor/resource required | Exact match; case-sensitive.       |
| `from`     | query | ISO-8601 UTC    | yes                  | Inclusive lower bound on `event_timestamp`. |
| `to`       | query | ISO-8601 UTC    | yes                  | Exclusive upper bound on `event_timestamp`. |
| `limit`    | query | integer         | no (default 100)     | `1 ≤ limit ≤ 500`.                          |

### API contract — subsequent page

| Param    | In    | Type    | Required | Notes                                              |
|----------|-------|---------|----------|----------------------------------------------------|
| `cursor` | query | string  | yes      | Opaque token from a previous response.             |
| `limit`  | query | integer | no       | May change between pages; subject to same bounds.  |

When `cursor` is present, **none of** `actor`, `resource`, `from`, `to`
may be supplied.

### Response — `200 OK`

```jsonc
{
  "items": [
    {
      "id":        "5b9c…-uuid",
      "timestamp": "2026-05-03T14:22:09.871Z",
      "actor":     "svc:billing",
      "action":    "invoice.created",
      "resource":  "invoice/4711",
      "outcome":   "SUCCESS",
      "context":   { "amount": 199.0, "currency": "EUR" }
    }
  ],
  "nextCursor": "eyJ0cyI6Ij…", // null when hasMore == false
  "hasMore":    true
}
```

### Errors — `400 Bad Request`

```json
{ "error": "INVALID_REQUEST", "message": "from must be before to", "field": "from" }
```

### Integration with arch layers → API layer

```
API layer  (com.auditlog.api)
  AuditEventController
   - @GetMapping("/audit-events")
   - parses query string into AuditEventQueryRequest (API DTO, package-private)
   - calls AuditEventQueryService.queryPage(...)
   - maps AuditEventPage → AuditEventPageResponse
   - @RestControllerAdvice maps ValidationError → 400
```

## Current state

- `com.auditlog.api.AuditEventController`:
  - `GET /audit-events` accepts
    `@RequestParam(required = false) actor, resource`,
    `@RequestParam from, to` (Instant),
    `@RequestParam(defaultValue = "100") limit`,
    `@RequestParam(defaultValue = "0") offset`.
  - Builds `AuditEventSearchCriteria`, calls `auditEventQueryService.find(...)`,
    returns `List<AuditEventResponse>` (200 OK).
  - DTOs `CreateAuditEventRequest` and `AuditEventResponse` are nested
    records inside the controller.
- No `@RestControllerAdvice` exists; Spring default error shape applies.
- `AuditEventQueryService.queryPage(AuditEventQuery)` exists from T5
  but no caller references it.

## Target state

- `GET /audit-events` accepts the new query parameters, calls `queryPage`,
  and returns the new `AuditEventPageResponse` envelope.
- `offset` is removed; `cursor` is added.
- New file `com.auditlog.api.GlobalExceptionHandler` maps validation +
  binding failures to the `{ error, message, field? }` body.
- New `AuditEventControllerMvcTest` covers each error path with
  `@WebMvcTest`; the existing controller integration test (if any) is
  updated to use cursor pagination.
- The legacy `POST` endpoint (event creation) is unchanged.

## Implementation plan

1. **Read the current controller in full.**
   - `cat src/main/java/com/auditlog/api/AuditEventController.java`.
   - Note the convention for inner DTOs (records nested in the
     controller class) and use the same convention for
     `AuditEventQueryRequest` / `AuditEventPageResponse`.

2. **Define the new request DTO.**
   - As a nested record on `AuditEventController` (or sibling file if
     that turns out to be the existing convention):
     ```java
     public record AuditEventPageResponse(
         List<AuditEventResponse> items,
         String nextCursor,
         boolean hasMore
     ) {}
     ```
   - There is no need for a dedicated `AuditEventQueryRequest` if the
     controller method signature uses `@RequestParam` directly; that
     keeps Spring's parameter-binding error handling intact.

3. **Replace the body of `GET /audit-events`.**
   - In `AuditEventController`:
     ```java
     @GetMapping("/audit-events")
     public AuditEventPageResponse query(
         @RequestParam(required = false) String actor,
         @RequestParam(required = false) String resource,
         @RequestParam(required = false) Instant from,
         @RequestParam(required = false) Instant to,
         @RequestParam(required = false) Integer limit,
         @RequestParam(required = false) String cursor
     ) {
       int effectiveLimit = (limit == null) ? 100 : limit;        // AC-2.6
       AuditEventQuery query = new AuditEventQuery(
           actor, resource, from, to, effectiveLimit, cursor);
       AuditEventPage page = auditEventQueryService.queryPage(query);
       List<AuditEventResponse> items = page.items().stream()
           .map(AuditEventResponse::fromView)                     // existing mapper or new
           .toList();
       return new AuditEventPageResponse(items, page.nextCursor(), page.hasMore());
     }
     ```
   - **Edge case — Instant binding.** Spring Boot's
     `DateTimeFormatterRegistrar` parses ISO-8601 into `Instant` by
     default. If `from` or `to` is malformed, Spring throws
     `MethodArgumentTypeMismatchException` — the advice in step 5
     maps that to `INVALID_TIMESTAMP`. AC-1.7 covered.
   - **Edge case — null limit.** Set to 100 *before* constructing the
     query so `validate()`'s `limitOutOfRange` rule sees the resolved
     value.
   - **Edge case — empty actor/resource.** Spring binds
     `?actor=` to `""`. The service's `validate()` treats blank as
     absent, so an empty string does not satisfy "at least one of".
     Document this behavior in the method body if it's surprising.
   - **Edge case — `offset` parameter.** Spring's default binding
     silently ignores unknown params. AC-2.7 / Open Question #5 in
     requirements.md flags this. Two options:
     - **Accepted behavior (recommended):** silently ignore `offset`
       per Open Question #5. Document with a comment.
     - **Stricter:** add a method-level guard
       `if (request.getParameter("offset") != null) throw new
       ValidationException(new ValidationError("INVALID_REQUEST",
       "Unknown parameter 'offset'; use 'cursor' instead.", "offset"));`.
       Requires injecting `HttpServletRequest` — extra coupling for
       small benefit. Default to silent-ignore.

4. **Map domain → response.**
   - `AuditEventResponse` already exists. Add a static factory
     `static AuditEventResponse fromView(AuditEventView v)` that maps
     `v.timestamp()` → ISO-8601 string and `v.context()` → the same JSON
     object Jackson serializes today. The exact mapping must produce the
     shape in design.md → Response.
   - **Edge case — outcome enum/string.** `AuditEventView.outcome()` is
     already a `String`; pass through unchanged so the body shows
     `SUCCESS|DENIED|ERROR`.

5. **Create the global exception handler.**
   - Path: `src/main/java/com/auditlog/api/GlobalExceptionHandler.java`.
   - Body:
     ```java
     @RestControllerAdvice
     public class GlobalExceptionHandler {

       public record ErrorResponse(String error, String message, String field) {}

       @ExceptionHandler(ValidationException.class)
       public ResponseEntity<ErrorResponse> handleValidation(ValidationException e) {
         ValidationError err = e.error();
         return ResponseEntity.badRequest()
             .body(new ErrorResponse(err.code(), err.message(), err.field()));
       }

       @ExceptionHandler(MethodArgumentTypeMismatchException.class)
       public ResponseEntity<ErrorResponse> handleTypeMismatch(MethodArgumentTypeMismatchException e) {
         // AC-1.7 — Instant parse failure on from/to.
         return ResponseEntity.badRequest()
             .body(new ErrorResponse("INVALID_TIMESTAMP",
                 "Parameter '" + e.getName() + "' must be ISO-8601 UTC.",
                 e.getName()));
       }

       @ExceptionHandler(MissingServletRequestParameterException.class)
       public ResponseEntity<ErrorResponse> handleMissingParam(MissingServletRequestParameterException e) {
         return ResponseEntity.badRequest()
             .body(new ErrorResponse("MISSING_PARAMETER",
                 "Parameter '" + e.getParameterName() + "' is required.",
                 e.getParameterName()));
       }
     }
     ```
   - **Edge case — IllegalArgumentException.** T5 already converts
     `AuditEventCursor.decode`'s `IllegalArgumentException` into
     `ValidationException` before it leaves the service. Do *not* add
     an `IllegalArgumentException` handler here, or domain-level
     validation in `AuditEvent`'s constructor will be silently shaped as
     a 400 too. Let unexpected `IllegalArgumentException` propagate to
     500.

6. **MVC slice test.**
   - Path: `src/test/java/com/auditlog/api/AuditEventControllerMvcTest.java`.
   - `@WebMvcTest(AuditEventController.class)` with `@MockBean
     AuditEventQueryService` (or `@MockitoBean` if Spring 6.2+).
   - Test methods, one per validation path:
     - `query_happyPath_returnsEnvelope` — stub the service to return a
       page; assert JSON body has `items`, `nextCursor`, `hasMore`.
     - `query_missingFilter_returns400MissingFilter` — stub the service
       to throw `ValidationException(missingFilter())`; assert body
       `{ error: "MISSING_FILTER", … }`.
     - `query_missingFrom_returns400MissingParameter` — likewise.
     - `query_fromAfterTo_returns400InvalidTimeWindow`.
     - `query_windowTooLarge_returns400WindowTooLarge`.
     - `query_limitOutOfRange_returns400LimitOutOfRange`.
     - `query_cursorWithFilter_returns400ConflictingParameters`.
     - `query_invalidCursor_returns400InvalidCursor`.
     - `query_invalidTimestamp_returns400InvalidTimestamp` — pass
       `from=not-a-date`; rely on Spring's parse error → advice.
   - **Edge case** — when stubbing the service to throw, Mockito's
     `doThrow(...).when(service).queryPage(any())` works; ensure the
     thrown exception is *unchecked* (`ValidationException extends
     RuntimeException`, so OK).

7. **Update the controller integration test.**
   - First check whether one exists: `find src/test -name 'AuditEventController*IntegrationTest*'`.
     The Phase 1 survey did not surface one; if absent, create
     `src/test/java/com/auditlog/api/AuditEventControllerIntegrationTest.java`
     using the existing Testcontainers bootstrap pattern.
   - Cases (full Spring context + real PG):
     - `getAuditEvents_returnsCursorPagedEnvelope` — seed 250 rows,
       call `GET /audit-events?actor=X&from=…&to=…&limit=100`, assert
       envelope shape; follow `nextCursor` twice and assert no
       duplicates over 3 pages.
     - `getAuditEvents_missingFilter_returns400` — happy-path smoke
       test of the advice through the full stack.
     - `getAuditEvents_offsetParameterIsSilentlyIgnored` — explicitly
       lock the Open-Question-#5 behavior.

8. **Run the full pipeline.**
   - `./gradlew unitTest integrationTest archUnitTest spotlessCheck` —
     all green.

9. **Manual smoke test.**
   - `./gradlew bootRun &`
   - Happy path:
     `curl -i 'http://localhost:8080/audit-events?actor=svc:billing&from=2026-05-04T00:00:00Z&to=2026-05-10T00:00:00Z&limit=10'`
     → 200, envelope.
   - Missing filter:
     `curl -i 'http://localhost:8080/audit-events?from=2026-05-04T00:00:00Z&to=2026-05-10T00:00:00Z'`
     → 400, `{ "error": "MISSING_FILTER", … }`.
   - Window too large:
     `curl -i 'http://localhost:8080/audit-events?actor=svc:billing&from=2026-04-01T00:00:00Z&to=2026-05-10T00:00:00Z'`
     → 400, `WINDOW_TOO_LARGE`.
   - `pkill -f bootRun` when done.
