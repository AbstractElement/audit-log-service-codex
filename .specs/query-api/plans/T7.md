# T7 — Cleanup: remove dead code and Flyway V4 drop old indexes

*Now that nothing references the old query path, remove it. Destructive
PR, intentionally separated from T6 so a regression there does not also
require reverting a schema drop.*

## Why this task exists

After T6 lands, the legacy `find(AuditEventSearchCriteria)` chain has zero
callers — but the code is still in the binary, the legacy indexes are
still on disk, and `AuditEventSearchCriteria` still pollutes the
Application layer with an offset-pagination concept that the new design
explicitly disallows (AC-2.4: cursor pins the filter set). This task is
the cleanup pass.

The split from T6 is deliberate. The rollback table puts T7 *last* among
the code tasks because two of its actions are non-reversible without an
extra migration:

1. Deleting `AuditEventSearchCriteria` and the legacy port/method removes
   compile-time references; a revert restores those, but reverts of T6
   would be cleaner if the legacy code were still present.
2. `DROP INDEX CONCURRENTLY` is a forward migration; rolling it back
   requires `V5__restore_legacy_indexes.sql`, not just a git revert.

So T7 only ships once T6 has soaked.

## Requirements covered

- *Out of scope* clause (requirements.md → Out of scope):
  > "Backwards-compatibility shim for the current offset/limit pagination
  > — callers will migrate to cursor pagination as part of this change."

  T7 closes that out-of-scope item by removing the shim.

(Nothing in this task introduces new behavior; it removes code paths that
T6 has already replaced.)

## Design references — extracts inlined

### Indexes → Indexes to drop

```sql
DROP INDEX CONCURRENTLY idx_audit_events_actor_timestamp;
DROP INDEX CONCURRENTLY idx_audit_events_resource_timestamp;
```

These are strict key-prefixes of the new indexes added in T1; PG will
choose the new indexes for any query the old ones served, so retaining
them only doubles the write amplification on every ingest.

### Integration with arch layers → Type changes summary

- `AuditEventSearchCriteria` (existing) is **replaced** by
  `AuditEventQuery` (T2). Replacing rather than evolving avoids the
  temptation of a hybrid cursor/offset shape, which would violate AC-2.4.
- `AuditEventRepository.find(...)` is **replaced** by
  `AuditEventRepository.findPage(...)` (T4). Single port method change,
  single integration test rewrite.
- `AuditEventQueryService.find(...)` (legacy) returns `List<AuditEventView>`
  and is no longer called by the controller after T6.

## Current state (assumes T6 is merged)

- `com.auditlog.application.AuditEventSearchCriteria` exists — record with
  `actor?, resource?, from, to, limit, offset`.
- `AuditEventRepository.find(AuditEventSearchCriteria)` is on the port.
- `JpaAuditEventRepository.find(...)` implements it via Criteria API.
- `AuditEventQueryService.find(AuditEventSearchCriteria)` orchestrates it.
- `AuditEventPersistenceIntegrationTest` has tests against `find(...)`.
- Database has 5 indexes on `audit_events` after T1:
  `audit_events_pkey`, `idx_audit_events_timestamp`,
  `idx_audit_events_actor_timestamp`,
  `idx_audit_events_resource_timestamp`,
  `idx_audit_events_actor_ts_id`,
  `idx_audit_events_resource_ts_id`.

## Target state

- `AuditEventSearchCriteria` deleted; no references remain anywhere.
- The port has only `save` and `findPage`.
- The adapter implements only those two.
- `AuditEventQueryService` exposes only `queryPage` (plus any other
  unrelated existing methods if present).
- `AuditEventPersistenceIntegrationTest` keeps only the
  save / immutability-trigger assertions; the legacy `find(...)` cases
  are removed.
- New migration `V4__drop_legacy_indexes.sql` ships the two drops.
- Database ends up with exactly 4 indexes (the PK plus the three named
  in the DoD).

## Implementation plan

1. **Confirm T6 has merged to master and master is green.**
   - `git log master --oneline` shows the T6 commit.
   - `./gradlew unitTest integrationTest archUnitTest` on master is
     green.
   - This task should be a fresh feature branch cut from master after
     T6 — typically still on `feature/audit-query-by-actor-resource`
     if T6 has not yet been rebased/merged; in that case the branch is
     already correct.

2. **Enumerate every legacy reference.**
   - Run: `grep -rn 'AuditEventSearchCriteria' src/`.
   - Expect hits in:
     - `src/main/java/com/auditlog/application/AuditEventSearchCriteria.java`
     - `src/main/java/com/auditlog/application/AuditEventRepository.java`
     - `src/main/java/com/auditlog/application/AuditEventQueryService.java`
     - `src/main/java/com/auditlog/infrastructure/persistence/JpaAuditEventRepository.java`
     - `src/test/java/com/auditlog/infrastructure/persistence/AuditEventPersistenceIntegrationTest.java`
     - Possibly the T5 unit-test fake repository.
   - Any unexpected hit (e.g. inside the API controller) is a sign that
     T6 left a stray caller; fix that before continuing.

3. **Delete `AuditEventSearchCriteria`.**
   - `git rm src/main/java/com/auditlog/application/AuditEventSearchCriteria.java`.

4. **Trim the port interface.**
   - File: `src/main/java/com/auditlog/application/AuditEventRepository.java`.
   - Remove the `List<AuditEvent> find(AuditEventSearchCriteria criteria);`
     declaration.
   - Remove the unused import line for `AuditEventSearchCriteria`.

5. **Trim the JPA adapter.**
   - File: `src/main/java/com/auditlog/infrastructure/persistence/JpaAuditEventRepository.java`.
   - Remove the `find(AuditEventSearchCriteria)` method body, any helper
     methods used only by it (private Criteria-builder code), and the
     associated imports.
   - **Edge case — keep `EntityManager` and Criteria-only imports if
     they are still used by `findPage(...)`'s native query path.**
     Native queries don't need Criteria API types, so most likely
     `jakarta.persistence.criteria.*` can go entirely.

6. **Trim the service.**
   - File: `src/main/java/com/auditlog/application/AuditEventQueryService.java`.
   - Remove the legacy `find(AuditEventSearchCriteria)` method (or
     whatever it was named pre-T7) and its imports.
   - **Edge case — read-only transaction annotation.** If the legacy
     method carried `@Transactional(readOnly = true)` and the new
     `queryPage` does not, decide whether to add the annotation. The
     adapter's `findPage` already has it; duplicating at the service
     layer is harmless but optional.

7. **Trim the integration test.**
   - File: `src/test/java/com/auditlog/infrastructure/persistence/AuditEventPersistenceIntegrationTest.java`.
   - Delete every test method that calls `find(...)`. Keep:
     - The save round-trip test.
     - The immutability-trigger test (proves the V2 trigger still
       blocks UPDATE).
   - **Edge case — class teardown.** If the test class had `@BeforeEach`
     seeding for the find tests, simplify or remove it.

8. **Trim the T5 unit-test fake.**
   - File: `src/test/java/com/auditlog/application/AuditEventQueryServiceTest.java`.
   - Remove the now-orphaned `find` method override from the
     `FakeRepository` since the port no longer declares it.

9. **Compile and run unit tests.**
   - `./gradlew compileJava compileTestJava`.
   - If any compile errors remain, they're stragglers from steps 3–8;
     fix them and re-run.
   - `./gradlew unitTest archUnitTest` — green.

10. **Create the V4 migration.**
    - Path: `src/main/resources/db/migration/V4__drop_legacy_indexes.sql`.
    - Contents:
      ```sql
      -- V4: drop the legacy two-column indexes superseded by V3's
      -- (filter, event_timestamp DESC, id DESC) composites. Keeping both
      -- doubles write amplification on every ingest.
      DROP INDEX CONCURRENTLY IF EXISTS idx_audit_events_actor_timestamp;
      DROP INDEX CONCURRENTLY IF EXISTS idx_audit_events_resource_timestamp;
      ```
    - **Edge case — `IF EXISTS`.** Use it so a re-run against an
      already-clean DB doesn't fail. (Idempotency matters when a test
      run hits a half-migrated container.)
    - **Edge case — `CONCURRENTLY` requires non-transactional execution.**
      T1 already set `spring.flyway.transactional: false`. If for any
      reason that setting was reverted, restore it before running this
      migration.

11. **Run integration suite.**
    - `./gradlew integrationTest` — green. Testcontainers re-applies V1
      through V4 against a fresh PG; the schema ends at the target
      state.
    - Add a focused integration assertion (in a small new test or by
      extending an existing one) that queries `pg_indexes` for
      `audit_events` and asserts exactly four index names:
      `audit_events_pkey`, `idx_audit_events_timestamp`,
      `idx_audit_events_actor_ts_id`,
      `idx_audit_events_resource_ts_id`.

12. **Run the full pipeline and the DoD greps.**
    - `./gradlew unitTest integrationTest archUnitTest spotlessCheck` —
      green.
    - `grep -rn 'AuditEventSearchCriteria' src/` → empty.
    - `grep -rn '\.find(' src/main/java/com/auditlog/application/` and
      confirm no result for the legacy method (the controller and
      service both call `queryPage(...)` now). Hits on `findPage` /
      `findById` etc. are fine.

## Dependencies + rollback

- **Dependencies.** T6 (must merge first so the legacy code has zero
  callers).
- **Rollback.** Code revert plus, **if V4 has already been applied to
  production**, a follow-up Flyway `V5__restore_legacy_indexes.sql` that
  re-creates the two dropped indexes:
  ```sql
  CREATE INDEX CONCURRENTLY IF NOT EXISTS idx_audit_events_actor_timestamp
    ON audit_events (actor, event_timestamp DESC);
  CREATE INDEX CONCURRENTLY IF NOT EXISTS idx_audit_events_resource_timestamp
    ON audit_events (resource, event_timestamp DESC);
  ```
  In dev / CI a fresh container start re-applies V1–V4 with no extra
  step needed.
