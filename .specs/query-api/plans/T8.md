# T8 — ArchUnit assertion: cursor stays in Application

*Lock in AC-5.1 with a static check so future refactors cannot push cursor
encoding into the API layer.*

## Why this task exists

The API layer must treat `nextCursor` as an opaque `String`. The cursor
record `AuditEventCursor` lives in `com.auditlog.application` (T2) and is
encoded/decoded by `AuditEventQueryService` (T5). If a future change ever
imports `AuditEventCursor` from `com.auditlog.api.*`, the layering rule
behind AC-5.1 is violated even if the rest of the system still works.

ArchUnit is the project's existing static enforcement mechanism
(`ArchitectureRulesTest`). This task adds two narrow rules:

1. **API → AuditEventCursor is forbidden.** The controller may only see
   the cursor as the `String` carried inside `AuditEventPage` /
   `AuditEventPageResponse`.
2. **AuditEventCursor must live in `..application..`.** Locks the class
   to that package; a future move to `com.auditlog.api.dto` would fail
   the build.

T8 is intentionally slotted *early* in the task graph — right after T2
adds the cursor type and before T6 wires the controller — so the rule
prevents a regression rather than catching one after the fact.

## Requirements covered

- **AC-5.1** (Ubiquitous) THE SYSTEM SHALL define cursor and request types
  in the Application layer; the API layer SHALL only translate HTTP
  ↔ Application DTOs.
- **AC-5.4** (Ubiquitous) ALL existing unit, integration, and ArchUnit
  tests SHALL continue to pass; new ACs SHALL be covered by:
  - unit tests for cursor encoding/decoding and validation rules,
  - a Testcontainers integration test that exercises pagination across at
    least 3 pages with concurrent inserts,
  - **an ArchUnit assertion confirming the new request/response types live
    in the correct layer.**

## Design references — extracts inlined

### Test coverage map → ArchUnit

> Existing rules already enforce that `AuditEventQuery`,
> `AuditEventCursor`, `AuditEventPage` live under
> `com.auditlog.application`. No new rule needed unless a new
> sub-package is introduced.

T8 makes this enforcement *explicit* and *cursor-targeted* — the existing
"Application classes must not depend on infrastructure" rule does not
catch a cursor moving to `com.auditlog.api`.

### Alignment with AGENTS.md → Architecture enforcement

> The existing `ArchitectureRulesTest` continues to enforce *API ↛
> Infrastructure*, *Application ↛ Infrastructure impls*, *Domain ↛
> Spring/JPA*. No new rule is required; one assertion will be added so
> that `AuditEventCursor` lives under `com.auditlog.application` to keep
> cursor encoding out of the controller.

## Current state

- `src/test/java/com/auditlog/architecture/ArchitectureRulesTest.java`
  exists and uses ArchUnit 1.3.0. It runs as part of the `archUnitTest`
  Gradle task.
- Rules currently enforced (per the Phase 1 survey):
  - API → Application only.
  - Application → no JPA / no Spring (with limited stereotype exceptions).
  - Domain → no frameworks.
  - JPA / Hibernate → Infrastructure only.
  - Persistence entities do not leak past Infrastructure.
  - Repository implementations match port interface.
  - No Infrastructure → API.
- The test class imports `JavaClasses` once (e.g. via a static field) for
  all rules. The new rules slot into the same field.
- `AuditEventCursor` is in `com.auditlog.application` after T2. No
  current code violates either rule, so adding them should pass first
  try.

## Target state

- Two new `@Test` methods in `ArchitectureRulesTest`:
  - `apiLayer_doesNotDependOnAuditEventCursor`
  - `auditEventCursor_residesInApplicationPackage`
- Both pass on the current code.

## Implementation plan

1. **Read the existing test class.**
   - `cat src/test/java/com/auditlog/architecture/ArchitectureRulesTest.java`.
   - Identify the `JavaClasses importedClasses` field (typical pattern)
     and confirm the package roots used in existing rules
     (`"..api.."`, `"..application.."`, `"..infrastructure.."`,
     `"..domain.."`).
   - Note the existing assertion style — directly chained `.check(...)`
     calls vs. `assertThat(rule).check(...)`. Match it.

2. **Add the API ↛ AuditEventCursor rule.**
   - Inside `ArchitectureRulesTest`:
     ```java
     @Test
     void apiLayer_doesNotDependOnAuditEventCursor() {
       noClasses()
           .that().resideInAPackage("..api..")
           .should().dependOnClassesThat().haveSimpleName("AuditEventCursor")
           .because("API must treat nextCursor as an opaque String (AC-5.1).")
           .check(importedClasses);
     }
     ```
   - **Edge case — `haveSimpleName("AuditEventCursor")`.** Locks the
     simple name globally. If anyone introduces a *different*
     `AuditEventCursor` in another package, this rule would still ban
     the API from depending on it. That's fine; we never want the API
     to take a hard dependency on a cursor type regardless of where it
     lives.

3. **Add the AuditEventCursor → ..application.. rule.**
   - Inside `ArchitectureRulesTest`:
     ```java
     @Test
     void auditEventCursor_residesInApplicationPackage() {
       classes()
           .that().haveSimpleName("AuditEventCursor")
           .should().resideInAPackage("..application..")
           .because("Cursor encoding belongs to the Application layer (AC-5.1).")
           .check(importedClasses);
     }
     ```
   - **Edge case — `.because(...)` ordering.** Some ArchUnit versions
     want `.because(...)` before `.check(...)`; the call above matches
     ArchUnit 1.x. Confirm by running the test.

4. **Compile and run the targeted ArchUnit task.**
   - `./gradlew archUnitTest --tests ArchitectureRulesTest` — both new
     tests should pass green on the current code.
   - If they fail, the failure message reports the violating class —
     fix the violation rather than relaxing the rule.

5. **Sanity-check that the rules actually trip on a violation
   (do not commit).**
   - In a scratch branch:
     - Add `import com.auditlog.application.AuditEventCursor;` to
       `src/main/java/com/auditlog/api/AuditEventController.java`.
     - Reference it: `AuditEventCursor.V` somewhere.
     - Run `./gradlew archUnitTest` — expect failure on
       `apiLayer_doesNotDependOnAuditEventCursor`.
   - Discard the scratch change. (Do *not* commit it.)
   - This step is optional but recommended once per project to ensure
     ArchUnit isn't silently misconfigured.

6. **Run the full pipeline.**
   - `./gradlew unitTest integrationTest archUnitTest spotlessCheck` —
     all green.
